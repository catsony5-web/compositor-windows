# 파일 정리와 용량 점검

2026-09-21 점검. 파일 수정·빌드·검증은 모두 백그라운드에서 진행했으며, 실행 중인 Morupixel이나 다른 데스크톱 프로그램을 조작하거나 종료하지 않았습니다. 이 작업 방식은 저장소의 [AGENTS.md](../AGENTS.md)에 기록했습니다.

## 파일 위치

| 위치 | 용도와 보관 기준 |
| --- | --- |
| `src/App`, `Core`, `Engine`, `Formats`, `UI`, `Tests` | 앱 소스와 회귀 테스트. 기존 책임별 구조 유지 |
| `tools/qa` | 보조 검증 도구 7개의 소스·프로젝트. 임시 산출물 폴더에서 이동 |
| `benchmarks/Interaction` | 화면을 띄우지 않는 성능 측정 도구 |
| `assets`, `models`, `licenses` | 글꼴·샘플·아이콘, 배경 제거 모델, 라이선스. 앱에 필요한 파일 |
| `docs` | 사용·설계·검증 문서. 이전 UI 검증 기록은 `docs/validation/ui-qa-0.1.txt` |
| `artifacts` | 새 테스트 결과, 성능 측정 결과, 용량 점검 기록 |
| `release` | 버전별 배포 ZIP·체크섬과 실행 폴더. 기존 버전의 검증 자료도 보존 |
| `src/bin`, `src/obj`, 도구별 `bin/obj` | 빌드로 재생성되는 캐시. 실행·빌드 중이면 정리하지 않음 |
| 루트 `tests` | 이전에 생성된 샘플 문서와 검증 결과. 기존 기록의 경로를 유지하기 위해 보존 |

보조 도구의 실행 방법과 결과 위치는 [tools/qa/README.md](../tools/qa/README.md)에 있습니다. 기능 회귀 검증의 기본 진입점은 계속 `scripts/Test.ps1`입니다.

## 용량과 조치

용량은 로컬 파일 길이의 합계입니다. OneDrive 자리 표시자와 재분석 지점은 제외하므로 실제 디스크 할당량이나 클라우드 사용량과는 다릅니다. GB는 10억 바이트, MiB는 1,048,576바이트입니다.

- 최초 점검은 약 **3.61 GB**였습니다. 앱 소스 자체보다 이전 버전 배포 파일과 여러 검증 도구의 반복 빌드가 대부분을 차지했습니다.
- 현재 앱 재빌드와 검증 자료를 포함한 정리 후 용량은 약 **2.65 GB**, 순감소는 약 **0.96 GB**입니다. [마지막 정리 기록](../artifacts/maintenance/20260921-182017-393.json).
- 기존 재생성 캐시 **1,015,233,412바이트(약 1.02 GB / 968.20 MiB)**를 정리했습니다. 삭제 항목은 [첫 정리 기록](../artifacts/maintenance/20260921-181305-623.json)에 남겼습니다.
- 플랫폼을 지정하지 않은 ONNX 빌드에는 Windows x64에서 사용하지 않는 Android·iOS·Linux·macOS·Windows ARM64 라이브러리가 복사돼 있었습니다. 기존 빌드 한 벌에서 약 **217 MiB**를 차지했습니다.
- `Directory.Build.props`에서 앱과 보조 프로젝트의 기본 대상을 Windows x64로 통일했습니다. 개발 빌드는 설치된 .NET을 사용하며, 배포 스크립트는 계속 .NET을 포함합니다. 새 앱 개발 출력은 약 **30.04 MB**이고 다른 플랫폼의 ONNX 파일은 없습니다.
- 옮긴 도구를 검증한 뒤 생성된 보조 `bin/obj` 약 **243 MB**도 정리했습니다. 이 양은 점검 과정에서 새로 생성한 파일이므로 기존 파일 정리량에 더해 절약량으로 계산하지 않았습니다. 현재 앱의 개발 빌드는 유지합니다.

배포 파일은 삭제하지 않았습니다. 최신 Preview 8은 실행 폴더 약 **205 MB**, ZIP 약 **96 MB**이며, .NET/WPF 런타임과 Windows ONNX 라이브러리·모델을 포함하므로 통째로 불필요한 캐시로 볼 수 없습니다.

모든 버전의 압축 해제 폴더는 합계 약 **1.75 GB**입니다. 점검 당시 실행 중인 버전과 최신 버전을 제외한 이전 폴더는 약 **1.36 GB**로, 추가 정리 후보입니다. 각 폴더에 대응하는 ZIP이 있고 파일 이름·크기가 일치하는지 확인했지만, 파일 내용 전체의 해시 비교까지 수행한 것은 아닙니다. 현재 작업과 복구 가능성을 위해 모든 ZIP과 실행 폴더를 유지했습니다.

## 다시 점검하거나 캐시 정리하기

저장소 루트에서 실행합니다. 기본 명령은 파일을 삭제하지 않고 보고서를 `artifacts/maintenance`에 저장합니다.

```powershell
.\scripts\Maintain.ps1

# 삭제 예정 경로만 표시하며 보고서도 쓰지 않음
.\scripts\Maintain.ps1 -CleanBuildCaches -WhatIf

# 현재 앱 빌드는 남기고 보조 도구 등의 캐시 정리
.\scripts\Maintain.ps1 -CleanBuildCaches -KeepCurrentBuild

# 앱의 bin/obj까지 포함하여 재생성 가능한 캐시 정리
.\scripts\Maintain.ps1 -CleanBuildCaches
```

정리 대상은 스크립트 안의 지정된 빌드 폴더로 제한합니다. 저장소 밖 경로와 재분석 지점은 거부하고, 실행 중인 앱·빌드와 파일 잠금을 확인해 사용 중인 폴더는 보존합니다. 프로세스를 종료하지 않습니다. 버전별 배포 폴더·ZIP·문서·샘플·모델·테스트 기록은 정리 대상에 포함하지 않습니다. 배포판에서 이미지 편집 등 데스크톱 작업을 계속할 수 있지만, 캐시 정리와 같은 출력 경로의 새 빌드를 동시에 시작하지는 마세요. 검사 직후 시작되는 빌드까지 잠금으로 막는 방식은 아닙니다. 삭제 도중 오류가 생기면 `Incomplete`로 기록하므로 해당 경로는 일부만 삭제되었을 수 있습니다.

앱 기능이나 버전은 변경하지 않았으며 배포 ZIP도 다시 만들지 않았습니다.
