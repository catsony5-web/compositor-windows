# Morupixel 데스크톱 편집 UI — 공식 레퍼런스 조사

조사일: **2026-09-21**. 목적은 오른쪽 속성 패널의 잘린 명령 이름과 시각적 혼잡을 줄이고, 사진 편집과 디자인 작업을 오래 수행할 수 있는 정보 구조를 정하는 것이다.

이 문서의 **확인 사실**은 제작사 공식 문서 또는 제작사 저장소에서 확인했다. **Morupixel 적용 판단**과 아래 수치는 이 앱의 WPF·한국어·마우스 작업 환경을 고려한 자체 설계안이다. 오래된 발표를 2026년에 새로 등장한 유행으로 표현하지 않는다. 공개 자료의 현재 제공 상태를 확인했으며, Adobe/Figma의 비공개 원본 설계 파일에는 접근하지 않았다.

## 1. Figma UI3 — 실제 편집기의 작업 효율과 라벨

- [Figma 디자인팀의 UI3 설계 회고](https://www.figma.com/blog/our-approach-to-designing-ui3/) — 게시일 2024-10-01.
- [현재 속성 패널 사용 안내](https://help.figma.com/hc/en-us/articles/360039832014-Design-prototype-and-explore-layer-properties-in-the-right-sidebar).

**확인 사실:** Figma는 초기 UI3의 떠 있는 탐색·속성 패널이 작은 화면과 장시간 작업을 방해한다는 피드백을 받고 기본 패널을 다시 도킹하고 크기를 조절할 수 있게 했다. 혼합 모드를 아이콘 뒤에 감추어 툴팁을 기다리게 하는 방식도 수정했다. 레이아웃 제어를 한곳에 모으고 선택한 대상에 맞는 속성을 우선 배치했으며, 라벨과 접근성 이름이 충분한 맥락을 전달하도록 조정했다. 현재 도움말은 사용자가 속성 라벨을 켤 수 있다고 안내한다.

**Morupixel 적용 판단:** 기본 작업 공간은 안정된 도킹 구조를 유지하고 사용자가 원하면 패널을 분리한다. 선택한 이미지·문자·도형에 맞는 속성을 먼저 보여 준다. `이름…`, `상세 변형…` 같은 축약 버튼 대신 `레이어 이름 변경`, `상세 변형 설정`처럼 행동을 알 수 있는 문장을 넓은 행에 표시한다. 도구 설명은 부가 설명으로 사용한다. 이름 전체를 알기 위한 필수 단계로 만들지 않는다.

이 자료는 실제 제품 UI와 설계 이유를 확인하기 위한 레퍼런스다. Figma 자체 편집기 전체를 복제할 수 있는 공식 `.fig` 파일을 확보했다는 의미는 아니다.

## 2. Microsoft Fluent 2 — 실제 Figma UI 키트와 Windows 글꼴

- [공식 Figma 디자인 리소스 안내](https://fluent2.microsoft.design/get-started/design).
- [Fluent 2 Web UI Kit 공식 진입 링크](https://aka.ms/Fluent2Toolkits/Web/Figma).
- [실제 Figma Community 파일](https://www.figma.com/community/file/836828295772957889/Microsoft-Fluent-2-Web).
- [타이포그래피](https://fluent2.microsoft.design/typography), [간격과 배치](https://fluent2.microsoft.design/layout), [디자인 토큰](https://fluent2.microsoft.design/design-tokens), [모서리와 선](https://fluent2.microsoft.design/shapes).

**확인 사실:** Microsoft 공식 페이지는 Figma 키트가 코드 라이브러리와 대응한다고 설명한다. 공식 진입 링크의 HTTP 리디렉션이 위 Community 파일을 가리키는 것도 확인했다. 다만 Figma 파일 본문은 웹 조사 도구의 robots 제한으로 열리지 않아 내부 프레임·컴포넌트 트리를 검사하거나 복제하지 않았다.

Fluent는 Windows에 Segoe UI 계열을 사용하고, 공식 Windows 글자 크기 표는 보조 글자 12px/16px, 본문 14px/20px를 제공한다. 간격은 4px 기반이며 필요에 따라 2·6·10px도 사용한다. 보통 크기의 버튼·드롭다운 모서리는 4px이고, 화면 가장자리까지 연결된 영역에는 둥근 모서리를 생략할 수 있다. 일반 글자 대비 기준은 4.5:1이다.

**Morupixel 적용 판단:** 운영체제 글꼴과 기존 한국어 폴백을 사용하고, 새 폰트 파일을 동봉하지 않는다. 조밀한 편집기 본문은 **13 DIP**, 보조 정보는 **12 DIP**, 섹션 제목은 **14 DIP**를 사용한다. 13 DIP는 Fluent 공식 기본 본문 크기를 그대로 사용한 것이 아니라 Morupixel에서 선택한 값이다. 입력칸 높이와 내부 여백을 확보하고 고정 높이 때문에 한국어 획이 잘리지 않도록 한다. 배치·색상·모서리는 공통 값으로 관리한다.

## 3. Adobe Spectrum / Spectrum 2 — 맥락, 대비, 크기 조절

- [Adobe Spectrum 2 공식 소개](https://s2.spectrum.adobe.com/).
- [Adobe Spectrum 공식 디자인 시스템](https://spectrum.adobe.com/).
- [공식 UI 키트 안내](https://spectrum.adobe.com/page/ui-kits/).
- [Tree view의 긴 이름과 크기 조절 지침](https://spectrum.adobe.com/page/tree-view/).

**확인 사실:** Spectrum 2 소개는 플랫폼과 사용 맥락에 맞는 유연성, 사용자 선호에 따른 크기·대비를 강조한다. Spectrum Tree view 지침은 긴 항목명을 줄여야 할 경우 전체 이름을 툴팁으로 제공하고, 깊은 계층에는 사용자가 조절할 수 있는 패널을 권장한다. 이는 가변적인 문서·레이어 이름에 관한 지침이며, 앱이 정한 짧은 동작 이름을 미리 줄여 쓰라는 근거는 아니다.

**리소스 확인 한계:** 현재 공개 검색 결과에서 Spectrum UI 키트는 XD 파일로 안내된다. UI 키트 페이지는 웹 조사 도구에서 JavaScript 요구 화면만 반환했다. **공식 Spectrum 2 Figma 원본 파일을 확보하거나 내부를 검증했다고 주장하지 않는다.** 제3자가 재제작한 Figma 파일을 Adobe 공식 파일로 취급하지 않는다.

**Morupixel 적용 판단:** 편집 패널 배경은 중성 색상으로 정돈하고 색상은 선택·초점·상태에 집중한다. 레이어명은 가변 콘텐츠이므로 줄 바꿈과 전체 이름 툴팁을 제공하되, 고정 명령 이름에는 충분한 너비를 우선 확보한다. 글래스 장식의 확산을 실무 편집기 전체의 필수 유행으로 간주하지 않는다.

## 4. Penpot Pencil — 공개된 실제 디자인 파일

- [Penpot 공식 Learning Center](https://penpot.app/learning-center) — Pencil을 Penpot 자체 디자인 시스템으로 소개.
- [Pencil 실제 디자인 파일](https://github.com/penpot/penpot-files/blob/main/Pencil-Penpot-Design-System.penpot).
- [공식 공개 디자인 파일 저장소](https://github.com/penpot/penpot-files).
- [작업 공간 사용 설명](https://help.penpot.app/user-guide/designing/workspace-basics/).
- [파일 배포·라이선스 설명](https://github.com/penpot/penpot-files/blob/main/CONTRIBUTING.md).

**확인 사실:** 공식 저장소에 편집 가능한 `Pencil-Penpot-Design-System.penpot` 파일이 공개돼 있으며, 조사 시 GitHub가 표시한 크기는 35.8 MB였다. 공식 안내에서 해당 시스템과 공개 라이브러리를 연결한다. GitHub 미리보기는 파일 크기 때문에 내용을 표시하지 않아 내부 화면을 열어 보거나 모든 컴포넌트를 분석하지 않았다.

**Morupixel 적용 판단:** 재사용 가능한 패널·행·라벨 스타일을 일관되게 구성하는 실제 공개 파일의 후속 검토 출처로 남긴다. 한 화면의 모양만 모방하기보다 반복되는 컨트롤의 규칙을 정한다.

## Morupixel 적용 기준

아래는 위 자료를 종합해 Preview 11에 적용한 **자체 설계 기준**이다. 외부 키트에서 추출한 정확한 토큰값이 아니다. 검증 범위는 아래에 따로 기록하며 릴리스 노트와 검증 보고서에서도 확인할 수 있다.

| 항목 | 적용 기준 |
| --- | --- |
| 글꼴 | Segoe UI 계열 + 맑은 고딕 폴백. 주 정보 13 DIP, 보조 정보 12 DIP, 섹션 제목은 14 DIP Semibold |
| 텍스트 배치 | 라벨은 왼쪽 정렬, 수치는 오른쪽 정렬. 가변 설명과 긴 이름은 줄 바꿈, 고정 명령은 완전한 이름 표시 |
| 간격 | 4/8/12/16 DIP를 기본 단계로 사용. 패널 좌우 여백 12~16 DIP, 섹션 사이 간격 12~16 DIP |
| 입력칸 | 숫자 입력은 최소 34 DIP 높이. 한글 폰트의 실제 높이와 DPI 배율에 맞춰 측정. 고정 높이에 맞추기 위한 글자 축소 금지 |
| 패널 너비 | 오른쪽 패널은 기본 396 DIP, 사용자가 324~520 DIP 사이에서 조절 |
| 속성 구조 | 레이어 식별 → 문자·도형 같은 대상별 속성 → 혼합·불투명도 → 위치·크기·회전 → 레이어 작업 순으로 묶음 |
| 숫자 속성 | X/Y, 너비/높이 같은 실제 쌍은 두 열. 긴 동작 버튼을 세 개씩 작은 상자로 나누지 않음 |
| 동작 | `Theme.ActionRow`는 최소 38 DIP의 전체 너비 행과 줄 바꿈으로 명령 이름 전체 표시. 진입 화살표보다 텍스트 영역을 우선 배정하고 같은 전체 이름을 접근성 이름에도 설정 |
| 시각 계층 | 평평한 중성 패널, 필요한 위치의 얇은 구분선, 4 DIP 정도의 컨트롤 모서리. 여러 겹의 카드·강한 광택·큰 필 버튼을 줄임 |
| 탭과 전환 | 명확한 선택 표시 하나, 충분한 클릭 영역. 사진 편집/디자인과 RGB/CMYK 인쇄 미리보기는 양쪽 목적지가 계속 보이는 분할 선택 컨트롤 사용 |
| 사진 편집 | 보정, 선택, 마스크, 브러시, 리터치를 우선 배치 |
| 디자인 | 도형, 문자, 색상, 정렬, 그룹을 우선 배치. 한 문서에서 이미지·문자·도형을 함께 쓰는 기존 모델은 유지 |
| 검증 | 작은 너비·기본 너비, 도킹·분리, 100%·150% 패널 매트릭스와 대표 200% 사례. 한국어·긴 레이어명·문자/도형 속성, 실제 명령 이름의 잘림과 불필요한 축약 검사 |

특히 `TextTrimming` 발생 여부만 검사해서는 `이름…`처럼 **소스 문자열 자체가 축약된 문제**를 발견할 수 없다. 자동 크기 검사와 실제 문구 검토를 함께 수행한다. 버튼 이름을 완전하게 바꾸면 줄 수와 클릭 영역도 함께 재측정해야 한다.

Preview 11의 오프스크린 패널 검사 **210개 캡처에서 글리프 잘림·축약 동작 이름 문제가 0건**이었다. 이 수치는 위 배율·상태에서의 패널 검사 결과다. 모든 Windows 배율이나 모든 사용자 문서에서의 무결성을 보증하는 표현으로 사용하지 않는다.

## 재사용 범위

이번 조사에서는 링크, 공개 설명, 배치 원칙을 참고했다. 외부 키트의 로고·아이콘·폰트·컴포넌트 파일을 Morupixel에 복사하거나 배포하지 않았다. Figma Community에서 공개돼 있다는 사실은 모든 자산의 무제한 재배포를 의미하지 않는다. Penpot 저장소는 별도 표기가 없는 자체 `.penpot` 콘텐츠에 CC BY 4.0을 적용하고, 포함된 제3자 콘텐츠에는 그 콘텐츠의 별도 라이선스가 적용된다고 설명한다. 실제 파일을 재사용하는 경우에는 해당 파일의 조건을 별도로 따른다.
