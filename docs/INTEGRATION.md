# 통합과 배포

공식 소스는 `catsony5-web/compositor-windows`의 `main` 하나입니다. Preview 22는 별도 작업에 있던 CAD 객체 가져오기, PDF/AI 레이어·벡터, 디자인 렌더링, 정밀 마술봉, 이동·자석 정렬, AI 연결을 합친 버전입니다.

## 다른 작업에서 기능을 추가할 때

1. `scripts/StartFeature.ps1 -Name 기능이름`으로 최신 `origin/main`에서 `codex/기능이름` 브랜치와 별도 worktree를 만듭니다. 같은 폴더를 여러 작업에서 동시에 편집하지 않습니다.
2. 변경을 커밋하고 기능 브랜치를 push한 뒤 `main` 대상 PR을 만듭니다. 설명에는 사용자 동작의 변화와 검증 결과를 적습니다.
3. 다른 PR이 먼저 합쳐졌다면 최신 `origin/main`을 기능 브랜치에 merge하고 충돌을 해결한 뒤 다시 검사합니다. 기존 기능을 삭제해서 충돌을 해결하지 않습니다.
4. **Build, self-test, and package**가 최신 코드에서 통과해야 병합합니다. 기능 브랜치의 로컬 ZIP을 공식 최신 버전으로 안내하지 않습니다.
5. `main`의 앱 변경은 GitHub Actions가 다시 빌드하고 소스·포터블 실행 파일을 모두 검사한 뒤 ZIP과 SHA-256을 공개합니다. 태그로 실행해도 `main`에 포함된 커밋만 배포할 수 있습니다.
6. 홈페이지는 완성된 GitHub 릴리스 중 가장 높은 버전의 ZIP·체크섬·표시 버전을 함께 반영합니다. 정적 페이지의 오프라인 대체 링크도 공개 릴리스에서 스냅샷을 갱신해 배포합니다.

`main` 보호는 PR, 최신 기준 브랜치와의 검사, 대화 해결을 요구하고 강제 push와 삭제를 금지합니다. 개인 저장소의 자체 PR도 검사 후 합칠 수 있도록 별도 사람의 승인은 필수로 하지 않습니다. GitHub Actions 결과와 배포 파일이 최종 기준입니다.

## 버전과 로컬 실행

공식 버전 번호는 통합 PR에서 결정합니다. 기존 번호가 다른 커밋에 이미 배포되었다면 자동화가 고유한 빌드 번호를 붙이며 기존 ZIP과 태그를 덮어쓰지 않습니다. 개발 중 기능 브랜치는 이름과 커밋을 함께 안내합니다.

사용 중인 이전 실행 폴더는 그대로 보관하고 새 버전은 별도 폴더에 설치합니다. 배포 파일을 확인한 뒤 고정 실행 바로가기만 새 버전으로 전환합니다. 열려 있는 창은 실행 당시 버전으로 계속 동작하므로 저장 후 고정 바로가기로 다시 열어야 업데이트가 적용됩니다.

Preview 19~21의 분리된 로컬 작업 기록은 보관용입니다. 새 기능 작업의 시작점으로 사용하지 않습니다. 홈페이지 디자인 변경도 홈페이지 소스를 먼저 저장하고 공개 배포가 끝난 뒤 완료로 보고합니다.
