# 공개 소스와 개인 작업 분리

공개 저장소에는 재현 가능한 앱 소스, 공용 개발 지침, 익명 검증 요약, 생성한 샘플과 라이선스를 확인한 테스트 파일만 보관합니다. 개인 도면·사진·회사 자료·대화 기록·계정 설정은 넣지 않습니다.

- `.env` 및 환경별 값 파일, 개인 `CLAUDE.md`와 로컬 AI 설정, 인증정보·비밀키는 Git 제외 대상입니다. 공개 환경 템플릿에는 실제 값을 쓰지 않습니다.
- `AGENTS.md`는 공용 개발 규칙입니다. 개인 프로필이나 작업 이력을 보관하는 파일로 사용하지 않습니다.
- 개인 입력과 검증 결과는 제외된 `artifacts/`에 둡니다. 공개 검증 문서는 입력 파일명, 고객·프로젝트명, 개인 컴퓨터 경로를 익명화합니다. 제외 규칙은 이미 추적된 파일을 자동으로 제거하지 않으므로 추적 파일 검사도 실행합니다.
- `scripts/TestPrivacy.ps1`은 추적 파일을 검사하고, `-Staged`는 커밋 예정 내용을 검사합니다. CI와 `Publish.ps1`에도 검사가 연결됩니다. 검사 로그는 규칙·파일·행만 보여 주며 발견된 값을 다시 출력하지 않습니다.
- 배포 시 개인정보 검사를 통과한 파일만 ZIP으로 만들고, 앱 디버그 심볼은 배포하지 않습니다. 빌드 경로는 `/_/`로 정규화합니다.

커밋 작성자는 공개 메타데이터입니다. GitHub **Settings → Emails → Keep my email addresses private**를 확인하고, 저장소의 `user.email`에는 계정의 검증된 GitHub noreply 주소를 사용하세요. GitHub CLI로 PR을 병합할 때도 `--author-email`로 같은 주소를 명시합니다. 계정 설정과 로컬 Git 설정은 별개입니다.

파일 삭제·익명화 커밋은 과거 커밋, 태그, PR 참조, 기존 ZIP을 소급해서 지우지 않습니다. 이미 공개된 민감정보는 자격증명 폐기, Git 이력 재작성, 영향받은 배포물 회수 및 GitHub의 캐시·참조 정리가 별도로 필요할 수 있습니다. 이력 재작성은 커밋 ID와 태그를 바꾸므로 백업과 팀 조율 후 진행합니다. 패턴 검사는 알려진 형태를 찾는 방어 수단이며, 모든 개인정보나 비밀정보의 부재를 보장하지 않습니다.
